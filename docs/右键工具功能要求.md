
##### 一、概述

**1.1 定位与目标**

RightKit 是一款面向 macOS 的 Finder 右键增强工具，通过 Finder Sync 扩展向右键菜单注入常用操作，追求极简、快速与可扩展。

**1.2 设计理念**

1. 功能设计追求极简，同时保留必要的灵活性：重点提供新建文件、复制路径、压缩/解压等常用功能，并支持 Shell 脚本扩展。常用功能应满足大多数用户的需求；更复杂的操作，用户可以添加自定义 Shell 脚本实现。

2. 避免重复造轮子。Keka 等第三方压缩软件已经足够成熟，右键工具直接调用这些软件完成压缩和解压即可，无需集成过多功能，以免软件变得臃肿。

3. UI 应尽量简洁、美观。

4. 软件架构应兼顾快速响应、健壮性和低功耗。



##### 二、项目基本信息

- 显示名：RightKit
- Bundle Identifier：`com.dozecat.RightKit`
- 目标系统：macOS 13 Ventura 及以上
- 分发方式：独立分发（非 Mac App Store），不开启 App Sandbox，需开发者签名与公证
- 更新机制：v1 不集成自动更新，用户手动下载新版本
- 本地化：中英双语（zh-Hans / en），跟随系统



##### 三、功能需求

**3.1 新建文件**

- 入口：仅在 Finder 空白处（无选中项）右键时显示「新建文件」子菜单。
- 交互：子菜单列出可用模板（内置 + 用户自定义）；点击某个模板后弹出输入框，用户输入文件名，确认后创建。
- 规则：
  - 创建位置：当前目录。
  - 内置模板：纯文本 `.txt`、Markdown `.md`，以及 Office 文档（Word `.docx`、Excel `.xlsx`、PowerPoint `.pptx`）。
  - 用户自定义模板：放入约定目录即生效。
  - 重名处理：自动追加序号，例如 `未命名.txt` → `未命名 2.txt`。
- 异常：无写权限等错误以通知提示。
- 待定：无。

**3.2 复制路径**

- 入口：右键菜单提供「复制绝对路径」单项，无子菜单。
- 交互：点击后把路径写入剪贴板。
- 规则：
  - 有选中项：复制选中项的绝对路径，多选时每行一个。
  - 空白处：复制当前目录的绝对路径。
- 待定：无。

**3.3 压缩/解压**

- 入口：
  - 压缩：选中文件/文件夹时右键，显示「压缩」。
  - 解压：仅当选中项包含受支持的压缩格式（zip/7z/rar/tar/gz…）时显示「解压」，否则隐藏；空白处不显示。
- 交互：
  - 压缩：调用第三方工具，每次弹窗让用户选择压缩格式（zip/7z/…）。
  - 解压：参考 Windows 右键习惯，提供「解压到当前文件夹」「解压到 <压缩包名>\」「解压到…（选择目标目录）」等菜单项。
- 规则：
  - 本期仅支持 Keka，需在设置界面检测/选择已安装的软件；未安装时给出提示。
  - 软件适配采用可插拔设计，便于后续扩展其他压缩软件。
  - 多选压缩包时逐个解压。
  - 同名冲突：默认弹窗询问（覆盖 / 跳过 / 重命名，支持「应用于全部」），与 Windows 习惯一致。
  - 进度反馈：优先复用 Keka 自带的进度窗口；无法复用时退化为完成通知。
  - 加密包：检测到加密时弹窗输入密码，交由 Keka 处理。
- 异常：未安装软件、压缩/解压失败时以通知提示。
- 待定：Keka CLI 的调用方式（能否传格式/密码/冲突参数、是否复用其进度 UI）。

**3.4 脚本功能**

- 定位：内置功能（新建文件、复制路径、压缩/解压）由原生代码实现；脚本仅用于用户自定义扩展。
- 入口：按脚本声明的触发条件，在选中文件/文件夹或空白处右键时显示对应脚本菜单项；子目录映射为子菜单。
- 交互：点击后后台静默执行对应脚本。
- 规则：
  - 脚本来源：自动扫描固定目录 `~/Library/Application Support/RightKit/Scripts/`，每个功能为一个文件夹包，放入即生效。
  - 元数据：由文件夹内 `config.json` 声明（详见 6.4）。
  - 管理方式：文件为唯一事实源；设置界面仅作为便捷编辑器，负责导入脚本、命名、选图标并生成/更新 `config.json`，不修改 `script.sh` 正文。手工编辑文件后重新扫描即可同步。
  - 参数：所选文件/文件夹路径作为参数传入（`$@`，支持多选）。
  - 执行：统一经 XPC 服务执行，隔离主进程。
- 异常/反馈：执行结果通过系统通知反馈；失败可点击查看日志。
- 执行约定与安全：工作目录、环境变量、超时、并发、日志及校验规则见 6.4。



##### 四、界面需求

**4.1 整体布局**

- 主应用仅提供单一设置窗口，无菜单栏常驻图标。
- 采用 macOS 标准「边栏导航 + 内容区」（`NavigationSplitView`），边栏分组：
  - 功能：新建文件、脚本、压缩
  - 其他：通用、关于
- 需要「列表 + 详情」的页面（新建文件、脚本）用三栏：边栏 | 列表 | 检查器；简单页面（压缩、通用、关于）用单栏表单。
- 设定窗口最小尺寸，避免内容拥挤。

**4.2 各页面设计**

- 新建文件：列表展示内置与用户模板（图标 + 名称 + 类型徽标），支持拖拽排序、增删；工具栏提供「添加模板」「在 Finder 中显示」；选中项在检查器中改名、换图标、预览内容。
- 脚本：
  - 列表展示脚本包（启用开关 + 名称 + 触发场景徽标），支持拖拽排序。
  - 工具栏：「导入脚本」「新建脚本」「打开目录」「重新扫描」。
  - 导入/新建流程：选择或生成 `.sh` → 生成脚本包文件夹 → 表单填写名称、触发场景等 → 写 `config.json`；图标经文件选择器复制为 `icon.png`。
  - 检查器为元数据表单（名称/图标/触发场景/多选/扩展名/排序/确认），修改实时写回 `config.json`；仅改配置与图标，不触碰脚本正文。
  - 启用/禁用与排序覆盖存放于 App Group，不改动脚本包。
- 压缩：检测本机已安装的压缩软件并单选指定；未安装时提供安装引导。
- 通用：语言设置、Finder 扩展状态与「打开系统设置」按钮。
- 关于：版本、开源许可、项目链接。

**4.3 交互与视觉规范**

- 遵循 macOS HIG，使用 SF Symbols、系统控件与系统色，深浅色自适应，支持键盘导航与快捷键。
- 尽量就地编辑（inline），减少弹窗；删除模板/脚本等破坏性操作需二次确认。
- 中英双语。
- 极简美学：大量留白、弱化色彩、仅用一个强调色、大图标、信息层级清晰、每屏一个主操作；不照搬其「拖拽执行」主窗口形态，因为 RightKit 主窗口的职责是管理配置，操作入口在 Finder 右键。
- 高级字段（如脚本元数据）默认折叠，保持界面干净，需要时再展开。

**4.4 空状态与反馈**

- 列表为空时显示引导文案与主操作按钮（如「新建第一个脚本」）。
- 首次启动检测 Finder 扩展是否已开启，未开启则弹窗引导并跳转系统设置对应面板。
- 后台操作结果以系统通知反馈；设置窗口内使用轻量 toast/状态提示。



##### 五、非功能需求

- 性能：菜单构建需在 Finder 可接受的时间内完成，重活全部异步。
- 健壮性：脚本/压缩进程异常不得导致扩展崩溃；有超时与错误兜底。
- 低功耗：避免轮询与常驻高开销任务。
- 安全：脚本执行经 XPC 隔离；校验脚本存在与可执行权限（详见 6.4）。
- 可维护性：功能按模块解耦，压缩器、菜单项均为可插拔设计。



##### 六、技术方案

**6.1 架构与组件**

| 组件 | 类型 | 职责 |
| --- | --- | --- |
| `RightKit.app` | 主应用 | 设置窗口；管理模板、脚本、压缩软件配置；权限引导；发送通知 |
| `FinderSyncExtension` | Finder Sync 扩展 | 构建并响应右键菜单；把用户操作转交主应用 / XPC |
| `RightKitShared` | 共享框架/源码 | 数据模型、常量、App Group 存储访问，供主应用与扩展共用 |
| `ScriptXPCService` | XPC 服务 | 统一、可靠地执行用户 `.sh` 脚本，隔离主进程 |

**6.2 进程与通信**

- Finder 扩展受系统内存/生命周期约束，所有耗时操作（脚本、压缩）一律异步转交 XPC 或主应用，避免阻塞扩展。
- 扩展与主应用、XPC 通过 App Group 共享配置，通过 XPC/NSXPCConnection 通信。
- 结果反馈统一走系统通知（`UserNotifications`），失败通知可附带日志路径。

**6.3 数据与存储**

- 使用 App Group 容器存放配置与模板，供主应用与扩展共享。
- 目录约定（初稿）：
  - 配置：App Group 容器内 `config.json`
  - 用户模板：App Group 容器内 `Templates/`
  - 用户脚本：`~/Library/Application Support/RightKit/Scripts/`
  - 日志：`~/Library/Logs/RightKit/`

**6.4 扩展机制**

- 压缩器适配：定义统一适配器协议，Keka 作为首个实现，后续软件按协议接入。
- 脚本包结构：每个脚本功能为一个文件夹包，包含入口脚本与可选的配置、图标：

  ```
  Scripts/
    转换为 WebP/
      script.sh        # 必需，入口脚本
      config.json      # 可选，元数据，缺省用文件夹名与默认值
      icon.png         # 可选，菜单/界面图标
  ```

- 配置格式：选定 **JSON**（Foundation 原生支持，零依赖）。
- `config.json` 字段：

  ```json
  {
    "name": "转换为 WebP",
    "icon": "icon.png",
    "context": "selection",
    "multiple": true,
    "extensions": ["png", "jpg"],
    "confirm": false,
    "order": 10
  }
  ```

  - `name`：菜单显示名，缺省用文件夹名。
  - `icon`：图标文件名，缺省用内置默认图标。
  - `context`：`selection`（默认）/ `files` / `folders` / `background` / `all`，决定显示场景。
  - `multiple`：是否允许多选时显示。
  - `extensions`：按文件类型过滤（可选）。
  - `confirm`：执行前是否二次确认。
  - `order`：菜单排序权重，缺省按名称。
- 图标：支持 PNG（建议提供 @2x），缺省回退内置默认图标。
- 用户偏好：启用/禁用、排序覆盖存放于 App Group，不改动脚本包。
- 脚本执行约定（v1 固定，不支持覆盖）：
  - 工作目录：当前右键所在目录。
  - 环境变量：注入 `RIGHTKIT_DIR`（当前目录）、`RIGHTKIT_FILES`（换行分隔的选中路径）；脚本仍可用 `$@` 取参。
  - 超时：默认 300 秒，超时终止并通知。
  - 并发：逐个串行执行，避免资源争用。
  - 日志：写入 `~/Library/Logs/RightKit/Scripts/<脚本名>/`。
- 安全：非沙盒环境下不做签名校验，仅校验脚本文件存在且具备可执行权限。

**6.5 Finder 覆盖范围**

- Finder Sync 扩展仅在已注册的目录中生效。为让右键菜单尽量“到处可用”，采用如下策略：
  - 注册根目录 `/`，覆盖绝大多数本地路径。
  - 显式追加特殊目录：桌面 `~/Desktop`、文稿 `~/Documents`、iCloud 云盘 `~/Library/Mobile Documents/com~apple~CloudDocs`。
- iCloud 云盘走 File Provider，注册根目录不一定覆盖，必须单独注册其路径；若用户开启了「桌面与文稿文件夹」同步，桌面/文稿实际位于 iCloud 路径下，需一并处理。
- 注册根目录会带来一定的内存/性能开销，属于“全局注入”，需评估其影响。
- 仍有盲区：废纸篓、智能文件夹、搜索结果、网络卷等可能不显示；系统「服务（Services）」兜底方案 v1 暂不实现，列入后续版本。
