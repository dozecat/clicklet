
##### 一、概述

**1.1 定位与目标**

RightKit 是一款面向 macOS 的 Finder 右键增强工具，通过 Finder Sync 扩展向右键菜单注入常用操作，追求极简、快速与可扩展。

**1.2 设计理念**

1. 功能设计追求极简，同时保留必要的灵活性：重点提供新建文件、复制路径、压缩/解压等常用功能，并支持 Shell 脚本扩展。常用功能应满足大多数用户的需求；更复杂的操作，用户可以添加自定义 Shell 脚本实现。

2. 避免重复造轮子。Keka 等第三方压缩软件已经足够成熟，右键工具直接调用这些软件完成压缩和解压即可，无需集成过多功能，以免软件变得臃肿。

3. UI 应尽量简洁、美观。

4. 软件架构应兼顾快速响应、健壮性和低功耗。



##### 二、项目基本信息

- 显示名：RightKit
- Bundle Identifier：`com.dozecat.RightKit`
- 目标系统：macOS 13 Ventura 及以上
- 分发方式：独立分发（非 Mac App Store），不开启 App Sandbox，需开发者签名与公证
- 更新机制：v1 不集成自动更新，用户手动下载新版本
- 本地化：中英双语（zh-Hans / en），跟随系统



##### 三、功能需求

**3.1 新建文件**

- 入口：仅在 Finder 空白处（无选中项）右键时显示「新建文件」子菜单。
- 交互：子菜单列出可用模板（内置 + 用户自定义）；点击某个模板后**不弹输入框**，直接按默认名创建，并让 Finder 选中该文件、就地进入重命名状态，与系统自带「新建文件夹」一致。
- 规则：
  - 创建位置：当前目录。
  - 默认名：跟随系统语言，中文为 `新建文件.<扩展名>`，英文为 `Untitled.<扩展名>`（同 Finder 的「未命名文件夹」）。
  - 就地重命名需要「辅助功能」权限：未授权时仍会创建并选中文件，仅不自动进入重命名，用户按回车即可；设置界面「通用」页给出状态与授权入口。
  - 内置模板：纯文本 `.txt`、Markdown `.md`，以及 Office 文档（Word `.docx`、Excel `.xlsx`、PowerPoint `.pptx`）。
  - 用户自定义模板：放入约定目录即生效。
  - 重名处理：自动追加序号，例如 `未命名.txt` → `未命名 2.txt`。
- 异常：无写权限等错误以弹窗提示。
- 待定：无。

**3.2 复制路径**

- 入口：右键菜单提供「复制绝对路径」单项，无子菜单。
- 交互：点击后把路径写入剪贴板。
- 规则：
  - 有选中项：复制选中项的绝对路径，多选时每行一个。
  - 空白处：复制当前目录的绝对路径。
- 待定：无。

**3.3 压缩/解压**

- 入口：
  - 压缩：选中文件/文件夹时右键，显示「压缩」。
  - 解压：仅当选中项包含受支持的压缩格式（zip/7z/rar/tar/gz…）时显示「解压」，否则隐藏；空白处不显示。
- 交互：
  - 压缩：调用第三方工具，每次弹窗让用户选择压缩格式（zip/7z/…）。
  - 解压：参考 Windows 右键习惯，提供「解压到当前文件夹」「解压到 <压缩包名>\」「解压到…（选择目标目录）」等菜单项。
- 规则：
  - 本期仅支持 Keka，需在设置界面检测/选择已安装的软件；未安装时给出提示。
  - 软件适配采用可插拔设计，便于后续扩展其他压缩软件。
  - 多选压缩包时逐个解压。
  - 同名冲突：默认弹窗询问（覆盖 / 跳过 / 重命名，支持「应用于全部」），与 Windows 习惯一致。
  - 进度反馈：优先复用 Keka 自带的进度窗口；无法复用时退化为完成通知。
  - 加密包：检测到加密时弹窗输入密码，交由 Keka 处理。
- 异常：未安装软件、压缩/解压失败时以通知提示。
- 待定：Keka CLI 的调用方式（能否传格式/密码/冲突参数、是否复用其进度 UI）。

**3.4 脚本功能**

- 定位：内置功能（新建文件、复制路径、压缩/解压）由原生代码实现；脚本仅用于用户自定义扩展。
- 入口：脚本不再平铺在右键菜单里，而是**折叠为一个「脚本」子菜单**。子菜单在右键菜单中的位置与开关由工具箱中的「脚本」条目决定；子菜单内容 = 当前选区下**匹配且已启用**的脚本（按脚本声明的触发条件筛选）；没有匹配项时不显示该子菜单。
- 交互：点击后后台静默执行对应脚本。
- 规则：
  - 脚本来源：自动扫描固定目录 `~/Library/Application Support/RightKit/Scripts/`，每个功能为一个文件夹包，放入即生效。
- 内置脚本：随 App 分发的脚本包（`Resources/BuiltinScripts/`）在启动时**播种**进上述目录。四条规则：**不覆盖**用户已修改的包、**不复活**用户删除过的包、**会补上**后续版本新增加的包、**会升级**未被改动过的副本（依据 `seeded-scripts.json` 里记录的内容指纹判断是否被改过；指纹**只覆盖内置包提供的文件**，所以用户往包里加图标、笔记、附加脚本既不会被覆盖，也不会因此冻结后续更新；升级是「覆盖同名文件」而不是删目录重建，多出来的文件一律保留。旧版只记名字、没有指纹，这类记录允许一次性升级并补齐指纹）。
  目前内置两个：「用 VS Code 打开」（`context: all`、`multiple: true`，空白处右键即打开当前文件夹；未安装 VS Code 时回退默认程序）与「用 Python 运行」（`context: files`、`extensions: ["py"]`、`confirm: true`，多选时可依次运行；脚本自己补 PATH 并优先使用 Homebrew 的 python3）。两者的图标都取各自应用的真实图标，见下。
- 脚本内必须自行补 PATH：XPC 服务继承 launchd 的最小环境（`/usr/bin:/bin:/usr/sbin:/sbin`），Homebrew 的 `python3`/`node` 不在其中。
  - 元数据：由文件夹内 `config.json` 声明（详见 6.4）。
  - 管理方式：**文件为唯一事实源**。设置界面只负责启用/停用、删除脚本包、以及在 Finder 中打开脚本目录；脚本包由用户直接放进目录，App 在**每次激活时重新扫描**，所以放进去再切回来就能看到，无需重启。
  - 参数：所选文件/文件夹路径作为参数传入（`$@`，支持多选）。
  - 执行：扩展只提交脚本 ID；主应用校验菜单快照后经 XPC 服务执行。
- 异常/反馈：执行结果通过系统通知反馈；失败可点击查看日志。
- 执行约定与安全：工作目录、环境变量、超时、并发、日志及校验规则见 6.4。


**3.5 工具箱**

- 定位：基础的右键动作集合。启用状态、顺序均由设置界面管理，随菜单快照下发给扩展。
- 扩展本地执行的条目（不唤起主 App）：
  - 新建文件：为「新建文件」子菜单总开关，仅在空白处右键时出现。
  - 拷贝路径：有选中项时复制其绝对路径；空白处右键复制当前目录路径（空白处标题为「拷贝当前文件夹路径」）。
  - 拷贝文件名：复制选中项的文件名（不含路径），仅在有选中项时出现。
  - 在终端中打开：用 Terminal.app 打开当前目录。
- 需要主 App 执行的条目（只有主 App 允许运行外部命令）：
  - 压缩为 ZIP：`/usr/bin/zip -r -X`
  - 压缩为 7Z：`Keka --cli 7zz a -y`（macOS 无内置 7-Zip）
  - 解压到当前文件夹 / 解压到独立文件夹：zip 走 `/usr/bin/ditto -x -k`，其余格式走 `Keka --cli 7zz x`
  - 输出名与所选软件同名时自动追加序号；执行完成后在 Finder 中选中产物。
- 脚本：渲染为「脚本」子菜单，位置与开关随工具箱顺序；无匹配脚本时不出现。
- 压缩器：可选 Keka 或「系统自带」（macOS 的 `ditto`/`zip`/`tar`，用 `com.apple.archiveutility` 取系统图标）。能力分为 `createsFormats` 与 `archiveFormats` 两组，前者决定工具箱里出现哪些压缩命令。**系统自带不支持 7z**，选中它时工具箱中的「压缩为 7Z」会自动消失，非 zip 解压走 `tar`。
- 执行细节全部写入诊断日志（完整命令行 + 输出），失败时弹窗提示。
- 待定：自定义显示名称、拖拽排序、在编辑器中打开（需要应用选择器）。

**3.6 偏好迁移**

- `AppPreferences` 带 `version`；载入时若低于 `currentVersion` 则执行一次迁移并写回。
- v1 → v2：内置起始文档曾因资源缺失而无法创建，用户因此关闭了 Word/Excel/PowerPoint 模板。现在资源已随包分发且可正常创建，因此**一次性把这些内置模板恢复为启用**（保留用户设置的排序），其余偏好不动。


##### 四、界面需求

**4.1 整体布局**

- 主应用仅提供单一设置窗口，无菜单栏常驻图标。
- 采用 **Safari 设置风格**：窗口顶部为「图标 + 文字」横向页签栏，下方为单栏可滚动内容区。
  - 页签固定 5 项：通用、工具箱、新建文件、压缩解压、脚本。
  - 窗口固定尺寸（700 × 540），隐藏标题栏，页签栏即窗口顶部；居中排布并避开红绿灯按钮。
  - 选择页签采用「顶部图标页签 + 单栏内容」而非侧边栏：5 个入口始终同时可见，不需要「进入/返回」，也不会出现侧栏宽度抖动。
- 图标：列表中的条目尽量使用系统真实图标（应用图标、文件类型图标），而不是近似的 SF Symbol。
- 行样式（参考 1Capture）：整块内容自左内缩 150pt 使版面居中，标签在 140pt 列中**右对齐并带全角冒号**，控件紧随其后左对齐，行高 10pt 上下留白。**不使用** `Form(.grouped)` 的内嵌灰卡片，**也不使用分组标题**——分组之间只放一条分隔线。
- **不设小字说明行**：字号只保留 13pt 一档。状态与取值直接放进控件位——二态用「复选框 + 状态词」（如 `☑ 已启用` / `☐ 未授权`），只读取值用灰色文本。长文本（如目录路径）放进控件的 tooltip。
- 列表/表格类内容（工具箱、模板、脚本）使用**深浅交替的行底色**，并每一行的底色是**向内缩进 8pt、圆角 7pt 的卡片**（而非通栏色带），这样一行读起来是一个独立条目、离开窗口边缘，横向拖动也有了余量；拖动阴影由这张卡片投出，不会连带文字一起投影。由 `RightKit/Views/ReorderableRows.swift` 统一提供拖拽排序：被拖的行**连同行底色一起抬起**（与卡片同一个 7pt 连续圆角 + 阴影 + 1.2% 放大），其余行按弹簧动画上移/下移让位，松手后落位。被拖的行**同时跟随指针横向移动，但经过重度阻尼**（`horizontalDamping = 0.22`）并**封顶 ±26pt**：顺序是一维的，横向位移不携带任何信息，一比一跟随会让行滑出自己的列、破坏与表头共用的对齐；阻尼后只保留「被指针拿住」的物理感。卡片距窗口有 8pt 缩进，横向偏移的余量即来自这里；若仍觉得边缘碍眼，把封顶值调小即可。
- **只有被拖的那一行**不参与位置动画（否则跟不上指针），其余行一律走弹簧——注意这里是「按行」判断，不是整表开关：写成整表开关时，拖动期间所有行的动画都会被关掉，而偏移恰好只在这时变化，推挤就变成瞬移。动画参数集中在 `ReorderMotion`，并有单元测试锁定该不变量。
- 表格页的首列缩进（`settingsTableLeadingInset = 72`）小于标签/控件页的缩进（`settingsLeadingInset = 150`）——表格首列是图标而非右对齐标签，用 150 会把整张表压到右边。72 是按**卡片内留白对称**定的：行卡片距窗口 8pt，卡片左边缘到图标应等于复选框到卡片右边缘，实测两侧 65.5 / 61pt（原先 118 时是 110 / 65）。
- 「关于」不占用页签，按 macOS 惯例放在应用菜单（`关于 RightKit` 使用系统标准面板）；`⌘,` 打开设置窗口。

**4.2 各页面设计**

- **通用**：权限（辅助功能、Finder 扩展、通知均为「复选框 + 状态词」）、启动（登录时启动，`SMAppService`）、语言（界面语言，暂不可调）、数据位置（脚本目录、模板目录）、**重置设置（恢复出厂设置）**。
  - 恢复出厂设置只重置偏好（启用开关、排序、压缩软件），**不删除**脚本包、生成图标与模板文件，**也不清除**内置脚本播种账本——用户删掉的内置脚本不会被"重置"复活。需二次确认，弹窗里写明不动文件。
- **工具箱**：按「图标 · 显示名称 · 启用」三列表格排列基础功能，**启用开关在最右列**，**直接拖拽行调整顺序**，顺序即右键菜单中的先后；勾选与顺序写入偏好并立即反映到 Finder 菜单；归档类条目显示**所选压缩软件的真实图标**；当前提供拷贝路径、拷贝文件名、在终端中打开，三项均由扩展本地执行，不唤起主 App。
- **新建文件**：与工具箱同构的三列表格「图标 · 文件名 · 启用」，**启用开关在最右侧**，**拖拽行调整顺序**，图标使用系统真实文件类型图标（装了 Office 即显示 Word/Excel/PowerPoint 图标）。**列表必须显示被关闭的模板**，否则关掉之后就再也没有地方可以勾回来。不提供应用内增删——模板目录是唯一事实源，「通用」页的「模板目录：显示」可跳到该目录。
- **压缩解压**：「压缩软件」一行显示**所选软件的真实应用图标**（Keka 或系统「归档实用工具」）加下拉选择；未安装时显示「未安装」与下载入口。下方分为「可压缩格式」与「可解压格式」两组，**都随所选软件变化**——可压缩格式比可解压格式窄（rar 只能解、不能压；系统自带压不了 7z）。默认压缩格式、解压位置、同名冲突、加密包处理见 3.3，尚未实现。
- **脚本**：与工具箱同构的表格「图标 · 脚本名称 · 路径 · 启用」，**启用开关在最右列**，**拖拽行调整脚本在菜单里的顺序**（选中行以强调色浅底标出）。增删按钮作为**列表的尾行**（在最后一条之后、随列表滚动），**右对齐到「启用」列下方**，顺序 `+` 在前 `−` 在后；列表为空时同样跟在引导块之后，位置不跳：`+` **在 Finder 中打开脚本目录**（不做应用内文件选择器导入——脚本包结构由用户直接放置，目录即事实源），`−` 删除当前选中行的整个脚本包文件夹（**需二次确认**，且只允许删除脚本目录内的路径，未选中时禁用）；另支持选中后按 Delete 键删除。移除操作不触碰用户手写的 `script.sh` 正文；导入后仍可手工编辑文件并重新扫描同步。**双击一行**在 Finder 中打开该脚本自己的文件夹，空状态双击则打开脚本目录本身——改脚本、换图标都直接去那个文件夹。图标解析顺序见 6.4。
- 尚未实现的条目在界面上以「即将支持」标记，**不放无法生效的假开关**。

**4.3 交互与视觉规范**

- 遵循 macOS HIG，使用 SF Symbols、系统控件与系统色，深浅色自适应，支持键盘导航与快捷键。
- 尽量就地编辑（inline），减少弹窗；删除模板/脚本等破坏性操作需二次确认。
- **表格页不用 `List`**：`List` 会把被 `.offset` 移出自己位置的行**裁掉**（已用渲染实验确认），所以被拖动的行既抬不起来、也无法压到邻行之上；而 `onMove` 不允许自定义拖动时的外观，拖动预览只能是裸内容（没有行底色、没有圆角）。这三个表格条目很少，因此改用 `ScrollView` + `ReorderableRows`（见下）自行处理拖拽。
- **不要给 `List` 设 `defaultMinListRowHeight` 为 0**：AppKit 会报 `setRowHeight` 错误并把整张表画成 0 高（行全部消失）。行高由行内 padding 决定即可。
- **三个表格页的尾随结构必须一致**：行与列头都要有 `Spacer(minLength: 12)`。曾漏掉工具箱与新建文件页，导致同一列（启用）在脚本页比另两页靠右 12pt。
- **列头与控件对齐**：macOS 复选框控件会把方框画在自己布局框左侧约 6.5pt，因此「启用」列头文字需要 `settingsCheckboxHeaderNudge = -6.5` 才能落在勾选框正上方（已按渲染图逐像素校准）。
- **分组分割线左右等距**（`padding(.horizontal, settingsLeadingInset)`），单侧贴边会显得歪。
- 列表的增删入口作为**尾行**跟在最后一条之后（`+` 在前 `−` 在后），右对齐到最右列；不用钉在窗口底部的固定栏——条目少时按钮会离内容很远，关联性反而变弱。
- 中英双语。
- 极简美学：大量留白、弱化色彩、仅用一个强调色、大图标、信息层级清晰、每屏一个主操作；不照搬其「拖拽执行」主窗口形态，因为 RightKit 主窗口的职责是管理配置，操作入口在 Finder 右键。
- 高级字段（如脚本元数据）默认折叠，保持界面干净，需要时再展开。

**4.4 空状态与反馈**

- 列表为空时显示引导文案与主操作按钮（如「新建第一个脚本」）。
- 首次启动检测 Finder 扩展是否已开启，未开启则弹窗引导并跳转系统设置对应面板。
- 后台操作结果以系统通知反馈；设置窗口内使用轻量 toast/状态提示。



##### 五、非功能需求

- 性能：菜单构建需在 Finder 可接受的时间内完成，重活全部异步。
- 健壮性：脚本/压缩进程异常不得导致扩展崩溃；有超时与错误兜底。
- 健壮性：菜单快照**写入 App Group 失败时不得让设置界面变空**——目录扫描的结果照常展示，失败只记入诊断日志（影响范围仅是扩展看到的是旧菜单）。
- 低功耗：避免轮询与常驻高开销任务。
- 安全：脚本执行经 XPC 隔离；校验脚本存在与可执行权限（详见 6.4）。
- 可维护性：功能按模块解耦，压缩器、菜单项均为可插拔设计。



##### 六、技术方案

**6.1 架构与组件**

| 组件 | 类型 | 职责 |
| --- | --- | --- |
| `RightKit.app` | 主应用 | 设置窗口、操作协调器；接收 Finder 请求、展示交互、扫描脚本、编排压缩、发送通知 |
| `FinderSyncExtension` | Finder Sync 扩展 | 沙盒内构建右键菜单；复制路径；把其余操作写入 App Group 并唤起主应用 |
| `RightKitShared` | 共享源码 | 数据模型、请求协议、App Group 存储访问，供三个进程共用 |
| `ScriptXPCService` | XPC 服务 | 只接受主应用调用，按脚本 ID 校验后执行用户 `.sh` 脚本 |

**6.2 进程与通信**

- Finder 扩展受系统内存/沙盒约束，只处理菜单与复制路径；其余操作写入 App Group 请求并以 `rightkit://` URL 唤起主应用。
- 主应用内嵌的 XPC Service 只对包含它的主应用可见，因此扩展不得直连 XPC。
- 主应用读取请求并负责交互、脚本扫描与压缩编排；脚本任务再通过 `NSXPCConnection` 发往 XPC。
- 扩展与主应用、XPC 通过 App Group 共享快照和状态。
- 结果反馈统一走系统通知（`UserNotifications`），失败通知可附带日志路径。

**6.3 数据与存储**

- 使用 App Group 容器存放菜单快照、偏好、请求和模板，供主应用与扩展共享。
- 目录约定（初稿）：
  - 菜单快照与偏好：App Group 容器内 `State/`
  - Finder 请求：App Group 容器内 `Requests/`
  - 用户模板：App Group 容器内 `Templates/`
  - 用户脚本：`~/Library/Application Support/RightKit/Scripts/`
  - 日志：`~/Library/Logs/RightKit/`
- App Group ID 使用 `$(TeamIdentifierPrefix)group.com.dozecat.RightKit`，并在开发者账号中注册。

**6.4 扩展机制**

- 压缩器适配：定义统一适配器协议，Keka 作为首个实现，后续软件按协议接入。
- 脚本包结构：每个脚本功能为一个文件夹包，包含入口脚本与可选的配置、图标：

  ```
  Scripts/
    转换为 WebP/
      script.sh        # 必需，入口脚本
      config.json      # 可选，元数据，缺省用文件夹名与默认值
      icon.png         # 可选，菜单/界面图标
  ```

- 配置格式：选定 **JSON**（Foundation 原生支持，零依赖）。
- `config.json` 字段：

  ```json
  {
    "name": "转换为 WebP",
    "icon": "icon.png",
    "context": "selection",
    "multiple": true,
    "extensions": ["png", "jpg"],
    "confirm": false,
    "order": 10,
    "applicationBundleIdentifier": "com.microsoft.VSCode"
  }
  ```

  - `name`：菜单显示名，缺省用文件夹名。
  - `icon`：图标文件名，缺省用内置默认图标。
  - `context`：`selection`（默认）/ `files` / `folders` / `background` / `all`，决定显示场景。
  - `multiple`：是否允许多选时显示。
  - `extensions`：按文件类型过滤（可选）。
  - `confirm`：执行前是否二次确认。
  - `order`：菜单排序权重，缺省按名称。
  - `applicationBundleIdentifier`：借用某个应用的真实图标。用于内置脚本——「用 VS Code 打开」用 `com.microsoft.VSCode`，「用 Python 运行」用 `com.apple.python3`（命令行工具/Xcode 自带的 Python Launcher）。直接分发别人的图标有商标问题，因此只存 bundle id，运行期用 `NSWorkspace` 取图标。
- 图标解析顺序：`config.json` 的 `icon` 字段 → **包内直接放置的 `icon.png`**（无需改配置，方便用户管理）→ `applicationBundleIdentifier` 指定应用的真实图标 → 内置默认符号。`icon` 指向的文件不存在时不报错，直接落到下一级，所以删掉图标文件不会变成空白。
- 内置脚本的 `config.json` **显式声明** `"icon": "icon.png"`（便于查看与修改），但**仓库里不放这个文件**，见下。
- 内置脚本的 `icon.png` **由 App 在播种时于本机生成**（**每次启动都会检查**，缺失就补，因此早于该机制播种的老包也会补上）（取所指定应用的图标，64pt 存盘），**不随仓库分发**：那些图标属于各自的应用，放进仓库等于再分发他人商标；本机生成还附带一个好处——日后卸载该应用，图标仍在。生成的文件不参与指纹比对，用户可随时替换或删除（删除后回退到应用图标，下次启动若仍缺失则补回）。图标内写入 XMP `dc:description` 说明来源，提示**分享脚本包前先删掉它**——App 会在对方机器上重新生成，详见《第三方资源说明》。
  默认符号用 `chevron.left.forwardslash.chevron.right`（`</>`），**不要用 `terminal`**——那个符号和 Terminal.app 图标是同一个「圆角框 + `>_`」，会和「在终端中打开」撞脸。
- 用户偏好：启用/禁用、排序覆盖存放于 App Group，不改动脚本包。
- 脚本执行约定（v1 固定，不支持覆盖）：
  - 工作目录：当前右键所在目录。
  - 环境变量：注入 `RIGHTKIT_DIR`（当前目录）、`RIGHTKIT_FILES`（换行分隔的选中路径）；脚本仍可用 `$@` 取参。
  - 超时：默认 300 秒，超时终止并通知。
  - 并发：逐个串行执行，避免资源争用。
  - 日志：写入 `~/Library/Logs/RightKit/Scripts/<脚本名>/`。
- 安全：XPC 请求只携带脚本 ID，由服务端从 App Group 快照解析脚本路径；脚本必须位于受控目录且具备可执行权限。当前不把无沙盒 XPC 视为安全边界，只用于隔离崩溃与生命周期。

**6.5 Finder 覆盖范围**

- Finder Sync 扩展仅在已注册的目录中生效。为让右键菜单尽量“到处可用”，采用如下策略：
  - 注册当前用户主目录，覆盖桌面、文稿及用户文件。
  - 注册 `/Volumes`，覆盖外接磁盘和常用挂载卷。
  - 单独注册 iCloud 云盘 `~/Library/Mobile Documents/com~apple~CloudDocs`。
- iCloud 云盘走 File Provider，必须单独注册；若用户开启了「桌面与文稿文件夹」同步，桌面/文稿实际位于 iCloud 路径下，需一并处理。
- 不默认注册根目录 `/`，避免沙盒不可访问和全局监听带来的性能消耗。
- 仍有盲区：废纸篓、智能文件夹、搜索结果、网络卷等可能不显示；系统「服务（Services）」兜底方案 v1 暂不实现，列入后续版本。
