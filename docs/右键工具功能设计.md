##### 一、概述

**1.1 定位与目标**

RightKit 是一款 macOS 上的 Finder 右键增强工具，通过 Finder Sync 扩展向右键菜单注入常用操作，追求极简、快速与可扩展。

**1.2 设计理念**

1. 功能设计追求极简，重点提供新建文件、拷贝路径、压缩解压等常用功能，并支持 Shell 脚本扩展。常用功能覆盖大多数人的需求，更复杂的操作交给用户自己的脚本。
2. 避免重复造轮子。压缩与解压交给已有的压缩软件：装了 Keka 就用 Keka，否则退回系统自带的 `zip`、`ditto`、`tar`。
3. UI 简洁、美观，深浅色自适应。
4. 架构兼顾快速响应、健壮性与低功耗。

##### 二、项目基本信息

- 显示名：RightKit
- Bundle Identifier：`com.dozecat.RightKit`，扩展为 `com.dozecat.RightKit.FinderExtension`
- 目标系统：macOS 13 Ventura 及以上
- 应用形态：代理应用（`LSUIElement`）。没有 Dock 图标，启动时不打开窗口，设置与自检从状态栏图标进入
- 分发方式：独立分发（非 Mac App Store）。主应用不开沙盒，扩展是沙盒的，需开发者签名与公证
- 更新机制：v1 不集成自动更新，用户手动下载新版本
- 本地化：简体中文或 English，默认按系统语言决定，切换后立即生效

##### 三、右键菜单

**3.1 工具箱与显示条件**

工具箱是右键菜单的基础动作集合。条目、启用开关与顺序都在设置界面管理，写入偏好后随菜单快照下发给扩展，改完立刻反映到 Finder。默认九项：新建文件、拷贝路径、拷贝文件名、在此处打开终端、脚本、压缩为 ZIP、压缩为 7Z、解压到当前文件夹、解压到独立文件夹。

扩展自己完成的只有拷贝路径与拷贝文件名——写剪贴板在沙盒内是允许的，其余条目都要唤起主应用。

菜单按选中的内容过滤：

- 空白处右键只有四项：新建文件、拷贝路径、在此处打开终端、脚本。
- 拷贝路径与在此处打开终端在选中项和空白处都出现，两种情境标题一致；空白处不再叫「拷贝当前文件夹路径」。
- 拷贝文件名只在有选中项时出现。
- 压缩为 ZIP、压缩为 7Z 至少有一个选中项不是压缩包时才出现——全部是压缩包时再压一次没有意义。
- 解压两项只在选中项里至少有一个压缩包时出现。
- 是否算压缩包只看扩展名（zip、7z、rar、tar、gz、tgz、zst、lz4 等），与当前选了哪个压缩软件无关。
- Finder 的边栏与工具栏菜单里只放「拷贝路径」一项。

**3.2 新建文件**

入口是空白处右键，子菜单列出所有可用模板（内置 + 用户自定义）。点击后不弹输入框，直接按默认名创建，并让 Finder 选中该文件、就地进入重命名状态，与系统的「新建文件夹」一致。

- 创建位置是当前目录，默认名跟随系统语言：中文为 `新建文件.<扩展名>`，英文为 `Untitled.<扩展名>`。
- 就地重命名需要「辅助功能」权限。未授权时文件照常创建并选中，只是不自动进入重命名，用户按回车即可。发键不能用一个固定延迟去赌 Finder 的时序，而是轮询等 Finder 真正到前台（每 80ms 一次，最多 2.5s），到达后再等 200ms 让选中态落定，然后发回车。
- 内置模板五个：纯文本 `.txt`、Markdown `.md`，以及三个空的 Office 文档 `.docx`、`.xlsx`、`.pptx`。用户把文件放进模板目录即可增加模板。
- 重名自动追加序号，例如 `新建文件.txt` → `新建文件 2.txt`。无写权限等错误用弹窗提示。

**3.3 拷贝路径与文件名**

- 拷贝路径：有选中项时复制选中项的绝对路径，多选时每行一个；空白处复制当前目录的路径。
- 拷贝文件名：复制选中项的文件名，不含路径。

**3.4 在此处打开终端**

用 Terminal.app 在当前目录开一个窗口。名字不用「在终端中打开」——那会被读成「用终端打开所选文件」，而这个动作只是在此处开终端。必须由主应用执行：扩展是沙盒的，把任意目录交给另一个应用会被系统拒绝。

**3.5 压缩与解压**

压缩格式不在弹窗里选，而是菜单里各自一项：压缩为 ZIP、压缩为 7Z。

- 压缩为 ZIP 走 `/usr/bin/zip -r -X`；压缩为 7Z 走 `Keka --cli 7zz a -y`，macOS 没有内置 7-Zip。
- 解压时 zip 走 `/usr/bin/ditto -x -k`。选了 Keka，其余格式走 `Keka --cli 7zz x`；选了系统自带工具，只有 zip 与 tar 系（tar、gz、tgz、bz2、tbz2、xz、txz）能解，其余格式报「所选的压缩软件不支持」。
- 多选压缩包时逐个解压。输出名与已有文件重名时自动追加序号。
- 压缩、以及解压到独立文件夹，完成后在 Finder 中选中产物；解压到当前文件夹不再唤出 Finder——文件就解在当前目录里，没有新东西要展示。
- 完整命令行与输出写入诊断日志，失败弹窗提示。

压缩软件在设置界面于 Keka 与「系统自带」之间选择；没有明确选择时用已安装的那个，所以系统自带始终可用。能力分 `createsFormats` 与 `archiveFormats` 两组，设置界面显示的「可压缩格式」「可解压格式」和工具箱都读当前所选软件的这组值：系统自带压不了 7z，选中它时工具箱里的「压缩为 7Z」消失。Keka 未安装时设置界面显示「未安装」与下载入口。

**3.6 脚本**

脚本不铺在右键菜单里，而是折叠成一个「脚本」子菜单；它在菜单中的位置与开关由工具箱里的「脚本」条目决定。子菜单内容是当前选区下匹配且已启用的脚本，没有匹配项时不显示。

- 脚本来源是固定目录 `~/Library/Application Support/RightKit/Scripts/`，一个功能一个文件夹包，放进即生效。文件是唯一事实源，设置界面只负责启用/停用与删除。
- 入口脚本固定为 `script.sh`，需有可执行权限，缺少或不可执行的包会被扫描跳过；元数据由包内可选的 `config.json` 声明，字段有 `name`、`icon`、`context`（`selection` / `files` / `folders` / `background` / `all`）、`multiple`、`extensions`、`confirm`、`order` 与 `applicationBundleIdentifier`。后一个字段指定借用哪个应用的真实图标：内置的「用 VS Code 打开」靠它在播种时从本机的 VS Code 生成图标，这份图标不进仓库。
- 主应用每次激活时重新扫描脚本目录，放进去再切回来就能看到，无需重启。
- 执行时扩展只提交脚本 ID；主应用校验菜单快照后，把任务交给内嵌的 XPC 服务。脚本在选中的文件/文件夹上运行，工作目录是右键所在目录，参数以 `$@` 传入。
- 脚本内必须自己补 PATH：XPC 服务继承 launchd 的最小环境（`/usr/bin:/bin:/usr/sbin:/sbin`），Homebrew 的 `python3`、`node` 不在其中。
- 执行约定：环境里注入 `RIGHTKIT_DIR`（当前目录）与 `RIGHTKIT_FILES`（换行分隔的选中路径）；默认 300 秒超时，超时终止；逐个串行执行；日志写在 `~/Library/Logs/RightKit/Scripts/<脚本名>/`。`confirm: true` 的脚本执行前弹确认。结果通过系统通知反馈，失败通知里带日志的最后一行。
- 内置脚本两个：「用 VS Code 打开」与「运行 Python 脚本」，随 App 分发，启动时播种进脚本目录。四条规则：不覆盖用户改过的包、不复活用户删过的包、补上后续版本新增的包、升级未被改动过的副本。判定依据是 `seeded-scripts.json` 里的内容指纹，指纹只覆盖内置包提供的文件，所以用户往包里加图标、笔记、附加脚本既不会被覆盖，也不会冻结更新。

##### 四、设置界面

**4.1 窗口与入口**

主应用是代理应用，没有 Dock 图标，设置窗口从状态栏图标进入：状态栏菜单只有三项——打开设置…（⌘,）、检查运行状态…、退出，平时图标是应用图标的简化轮廓，访达扩展没有启用时换成警告三角，因为那时整个右键菜单都会消失，这是最需要一眼看出的状态。

设置窗口固定 700 × 540，隐藏标题栏，顶部是「图标 + 文字」的横向页签栏（Safari 设置风格），下方是单栏可滚动内容区。页签六项：通用、工具箱、新建文件、压缩解压、脚本、关于。选择页签用横向页签而非侧边栏，是因为六个入口可以始终同时可见，不需要「进入/返回」。

应用菜单只保留 App 菜单（关于、设置、退出）、编辑菜单的剪切/拷贝/粘贴（路径文本要能选中复制）与帮助菜单，文件、显示、窗口等 SwiftUI 自动生成的菜单组已按需移除：这个应用没有文稿概念，也只有一个固定尺寸的窗口，留着只会让人以为坏了。

**4.2 各页**

- **通用**：登录时启动（`SMAppService`）、语言、访达扩展开关、辅助功能、通知、脚本目录；模板目录只在该目录非空时出现，因为不放自定义模板时它只是一句无用的提示。语言在简体中文与 English 之间切换，立即生效、不重启：界面在渲染时按所选语言查对应的 bundle，扩展也从同一个偏好里取语言，同样不需要重载。恢复出厂设置只重置偏好（启用开关、排序、压缩软件），不删除脚本包、生成图标与模板文件，也不清除内置脚本的播种账本；需二次确认，弹窗里写明不动文件。
- **工具箱**：三列表格「图标 · 显示名称 · 启用」，开关在最右列，拖拽行调整顺序，顺序即菜单顺序。归档类条目显示所选压缩软件的真实图标。
- **新建文件**：三列表格「图标 · 文件名 · 启用」，同样拖拽排序，图标用系统真实文件类型图标。列表显示被关闭的模板，否则关掉之后就再也没有地方可以勾回来。不提供应用内增删，模板目录是唯一事实源。
- **压缩解压**：「压缩软件」一行显示所选软件的真实图标加下拉选择，未安装时显示「未安装」与下载入口；下面是「可压缩格式」与「可解压格式」两行，都随所选软件变化。
- **脚本**：四列表格「图标 · 脚本名称 · 路径 · 启用」，开关在最右列，拖拽排序。增删按钮是列表的尾行，`+` 在 Finder 中打开脚本目录（不做应用内文件选择器导入，目录即事实源），`−` 删除选中行的整个脚本包，需二次确认且只允许删除脚本目录内的路径。双击一行在 Finder 中打开该脚本自己的文件夹。
- **关于**：版本（含 build 号）、GitHub 项目主页、Releases 页面、许可与系统要求，并可打开系统标准关于面板。

**4.3 自检**

自检是一个 sheet，不占页签：它属于排障，不属于配置，而且正常情况下结论永远是「一切正常」，不值得占一个常驻入口。首次启动自动弹出一次，之后从「帮助 → 检查运行状态…」或状态栏菜单打开。它检查访达扩展是否启用、辅助功能与通知是否授权、App Group 容器是否可用、菜单快照是否新鲜、压缩软件是否安装、脚本目录是否可写，每项给出状态和能一键修复的按钮。

**4.4 界面约定**

- 遵循 macOS HIG：SF Symbols、系统控件与系统色，深浅色自适应。
- 行样式：内容自左内缩 150pt，标签在 140pt 列中右对齐，控件紧随其后左对齐；分组之间只放一条分隔线，不用 `Form(.grouped)` 的内嵌卡片，也不用分组标题。
- 列表页用「图标 · 名称 · 启用」三列（脚本页多一列路径），启用开关在最右列；行底色是向内缩进 8pt、圆角 7pt 的交替色卡片，拖拽排序由 `ReorderableRows` 统一提供。
- 表格页不用 `List`：`List` 会把被 `.offset` 移出自己位置的行裁掉，拖动中的行既抬不起来也压不到邻行之上，而且不允许自定义拖动时的外观。
- 列表显示被关闭的条目，否则关掉之后没有地方可以勾回来。

**4.5 菜单图标**

右键菜单项带图标。扩展是沙盒的，解析不了应用图标与文稿类型图标，所以主应用把它们渲染成 16pt PNG 放进菜单快照（`MenuSnapshot.icons`），扩展解码后设到 `NSMenuItem.image`。这些图标是模板图像，只带 alpha，颜色交给系统，浅色与深色菜单栏以及高亮时的反色都不用自己处理。图标让快照从约 4KB 涨到约 100KB，所以快照只在内容真正变化时才写盘（比较时排除 `generatedAt`），否则每次 App 激活都会白写一遍。

##### 五、架构与通信

**5.1 组件**

| 组件 | 类型 | 职责 |
| --- | --- | --- |
| `RightKit.app` | 主应用 | 设置窗口与自检；接收 Finder 请求，建文件、编排压缩、运行脚本、发送通知 |
| `FinderExtension` | Finder Sync 扩展 | 沙盒内构建右键菜单；拷贝路径与文件名；其余操作写成 App Group 请求并唤起主应用 |
| `Shared/` | 共享源码 | 数据模型、请求协议、App Group 存储访问，供三个进程共用 |
| `ScriptXPCService` | XPC 服务 | 只接受主应用调用，按脚本 ID 校验后执行用户 `script.sh` |

**5.2 进程与通信**

- 扩展受沙盒与系统内存约束，只处理菜单与剪贴板。其余操作写入 App Group 的请求文件，再用 `rightkit://action/<uuid>` 唤起主应用；打开 URL 失败时（例如应用刚被移动，scheme 还没注册）直接启动主应用，主应用在启动时会把请求目录里剩下的请求全部处理掉。
- 主应用内嵌的 XPC Service 只对包含它的主应用可见，因此扩展不得直连 XPC。
- 扩展与主应用通过 App Group 共享菜单快照与偏好；快照写盘后发一条 distributed notification，扩展收到再重新读取。
- 结果反馈统一走系统通知（`UserNotifications`），失败通知可附带日志路径。

**5.3 存储**

- App Group 容器（`$(TeamIdentifierPrefix)group.com.dozecat.RightKit`）：`State/` 放菜单快照与偏好，`Requests/` 放 Finder 请求，`Templates/` 放用户模板。
- 用户脚本：`~/Library/Application Support/RightKit/Scripts/`，与 App Group 容器分开；播种账本 `seeded-scripts.json` 在它的上一级目录。
- 日志：`~/Library/Logs/RightKit/`，脚本日志在其 `Scripts/` 子目录。
- 偏好 `AppPreferences` 带 `version`，载入时若低于当前版本就执行一次迁移并写回。v1 → v2 只做一件事：内置起始文档曾因资源缺失而无法创建，用户因此关掉了 Word/Excel/PowerPoint 模板；现在资源随包分发且能正常创建，于是把这些内置模板恢复为启用，保留用户设置的排序，其余偏好不动。

##### 六、约束与取舍

**6.1 沙盒**

扩展只能做不涉及其他应用、也不涉及任意路径的事，拷贝路径与文件名写剪贴板是安全的。凡是要把路径交给别的应用（开终端、压缩、解压），或要在任意位置读写文件（新建文件），都必须交给主应用；脚本也一样，扩展只提交脚本 ID。曾经把「在终端中打开」放在扩展里，代码看着合理但从未成功过。

**6.2 Finder 覆盖范围**

Finder Sync 扩展只在已注册的目录里生效，因此注册当前用户主目录、`/Users`、`/Volumes` 与 `/System/Volumes`，另外单独注册 iCloud 云盘 `~/Library/Mobile Documents/com~apple~CloudDocs`：iCloud 走 File Provider，必须单独注册；用户开启「桌面与文稿文件夹」同步时，桌面与文稿实际也在 iCloud 路径下。不注册根目录 `/`，避免不必要的全局监听。废纸篓、智能文件夹、搜索结果与网络卷仍有盲区。

**6.3 安全边界**

XPC 请求只携带脚本 ID，由服务端从 App Group 快照解析脚本路径，并校验脚本位于脚本目录内且具备可执行权限；删除脚本时也只允许删除该目录内的路径。当前不把无沙盒的 XPC 视为安全边界，它用于隔离崩溃与生命周期。
