# RightKit 项目结构

本文档说明工程目录、target 职责与分层规则。

## 一、架构总览

三个 target，共享源码以文件夹形式同时编入三者：

```
   RightKit.app          FinderSyncExtension        ScriptXPCService
  （设置界面）              （右键菜单）                （脚本执行）
        \                       |                         /
         \                      |                        /
          └──────────  Shared/（业务逻辑，普通文件夹）───┘
```

- 无独立 framework target，`Shared/` 只是源码，被三个 target 共同引用。
- 业务逻辑集中在 `Shared/`，三个 target 只保留各自入口与界面。
- 扩展 ↔ XPC 的协议定义在 `Shared/IPC.swift`。

## 三、target 与 Bundle Identifier

| Target | 类型 | Bundle Identifier | 职责 |
| --- | --- | --- | --- |
| `RightKit` | Application | `com.dozecat.RightKit` | 设置窗口、模板/脚本/压缩配置、权限引导、通知 |
| `FinderExtension` | Finder Sync Extension | `com.dozecat.RightKit.FinderExtension` | 构建右键菜单、转发用户操作 |
| `ScriptXPCService` | XPC Service | `com.dozecat.RightKit.ScriptXPCService` | 隔离执行用户脚本 |
| `RightKitTests` | Unit Test Bundle | `com.dozecat.RightKitTests` | 共享业务逻辑单元测试 |

`FinderExtension` 与 `ScriptXPCService` 由 `RightKit.app` 内嵌。

## 四、分层规则

| 层 | 位置 | 规则 |
| --- | --- | --- |
| View（界面） | `RightKit/Views/` | 只画界面、绑定数据、转发点击，不含业务逻辑 |
| Service（业务） | `Shared/Services.swift` | 真正干活的代码，不 import SwiftUI，可脱离界面测试 |
| Model（数据） | `Shared/Models.swift` | Codable 数据结构，无逻辑 |
| Storage / IPC | `Shared/Storage.swift`、`Shared/IPC.swift` | App Group 读写、XPC 协议与常量 |

判断标准：**能脱离界面单独运行、单独测试的代码 → 放 `Shared/`。**

`FinderExtension` 保持“薄入口”：只构建菜单并把操作转交 `Shared` 或 XPC，不写业务逻辑。

## 五、数据与通信

- 配置与模板：App Group 容器 `group.com.dozecat.RightKit`。
- 用户脚本：`~/Library/Application Support/RightKit/Scripts/`。
- 日志：`~/Library/Logs/RightKit/`。
- 脚本执行：扩展 → `ScriptXPCService`（`Shared/IPC.swift` 中的 `ScriptXPCProtocol`）。

## 六、XcodeGen 使用方法

工程文件 `RightKit.xcodeproj` 由 `project.yml` 生成，**不入库**。

```sh
# 首次安装
brew install xcodegen

# 生成 / 重新生成工程
xcodegen generate

# 打开
open RightKit.xcodeproj
```

以下情况需要重新执行 `xcodegen generate`：

- 修改了 `project.yml`
- 新增 / 删除 / 移动了源文件
